# perf-baseline reference fixture

Used by `scripts/perf-baseline.sh` to capture stable performance numbers.

## seed.ndjson

Deterministic ~10 MB dataset (~40k rows) generated by the Python block in F2.1
plan Task 5. Spans 24h of synthetic timestamps; 5 services; 3 severities;
searchable token values in `attributes`.

The file IS the contract — regenerating must produce identical bytes (same
input → same output). If you change the generator, re-baseline.

`perf-baseline.sh` ingests this dataset N times (default `--target-rows=100000`,
so ~2.5 copies) to reach the target row count.

## queries.txt

Reference query set exercising all three levels of the pruning cascade:

- `q-broad-scan` — no pruning; measures raw scan throughput.
- `q-time-prune` — narrow time-range; catalog-level pruning.
- `q-equality-prune` — equality on `service.name`; extent-stats pruning.
- `q-low-card-prune` — low-cardinality `severity_text`; another extent pruning angle.
- `q-token-prune` — `has` against `message`; block-level + index.
- `q-multi-prune` — combines time + service.name + severity grouping.

Each query runs K=10 times during measurement.

## Re-baselining

After changing seed.ndjson, queries.txt, or any engine behavior that legitimately
shifts perf numbers: trigger `.github/workflows/perf-baseline-capture.yml` via
`workflow_dispatch` on `ubuntu-22.04`. A PR with the new
`scripts/fixtures/perf-baseline.json` is opened automatically.

Local laptop captures are NOT valid baselines — they will differ enough from
GHA hosted runners to produce false-positive regressions.
