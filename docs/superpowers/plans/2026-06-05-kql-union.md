# KQL `union` Operator Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `union A, (B | where x), C | <ops>` works in kyma-KQL with ADX-default outer-by-name semantics (column superset, null-fill) and `withsource=Col`, so Discover's multi-source "Open in Query Editor" export becomes a real, runnable query.

**Architecture:** kyma-kql gains a schema-aware entry point `kql_to_sql_with_schemas(src, &SchemaMap)` (`SchemaMap = HashMap<String, Vec<String>>` of table → column names, insertion-ordered columns). `union` parses ONLY as the leading operator; operands are table names or parenthesized sub-pipelines (compiled recursively with the same parser into per-branch SQL). Lowering: compute the column superset across operands (first-seen order), emit one CTE per branch projecting `col-or-NULL AS col` (+ optional `'name' AS SourceCol` for withsource), then `SELECT … FROM (b0 UNION ALL b1 …)` with trailing pipe ops applied via the existing QueryState machinery over the union subquery. The schema-less `kql_to_sql` stays for non-union queries; union without schemas → clear ParseError ("union requires schema context").

**Investigation ground truth (2026-06-05):** kyma-kql has no AST — parser mutates QueryState directly (parser.rs:117-135 `parse_query` expects leading table ident; trailing-token error at :130). SQL assembly in state.rs:62-152 (flat SELECT + optional CTE prelude — graph ops already emit CTEs, follow their pattern). Call sites of `kql_to_sql`: find ALL (investigation found kyma-server/src/flight.rs:219; the HTTP `/v1/query` `application/x-kql` path may share or duplicate — grep `kql_to_sql` across the workspace and wire every site). DataFusion 44 / sqlparser 0.53: `UNION ALL` positional only — hence explicit per-branch projections. Golden-SQL test style in parser.rs:1053+.

**Branch:** `feat/kql-union` off main. Path-scoped commits.

```rust
fn schemas(pairs: &[(&str, &[&str])]) -> std::collections::HashMap<String, Vec<String>> {
    pairs.iter().map(|(t, cols)| (t.to_string(), cols.iter().map(|c| c.to_string()).collect())).collect()
}
fn must_with(src: &str, s: &std::collections::HashMap<String, Vec<String>>) -> String {
    kql_to_sql_with_schemas(src, s).expect("parse")
}

#[test]
fn union_two_tables_outer_by_name() {
    let s = schemas(&[("a", &["ts", "msg"]), ("b", &["ts", "code"])]);
    let sql = must_with("union a, b", &s);
    // Column superset in first-seen order: ts, msg, code.
    assert!(sql.contains(r#"SELECT ts, msg, NULL AS code FROM a"#), "{sql}");
    assert!(sql.contains(r#"SELECT ts, NULL AS msg, code FROM b"#), "{sql}");
    assert!(sql.to_uppercase().contains("UNION ALL"), "{sql}");
}

#[test]
fn union_with_source_column() {
    let s = schemas(&[("a", &["x"]), ("b", &["x"])]);
    let sql = must_with(r#"union withsource=src a, b"#, &s);
    assert!(sql.contains(r#"'a' AS src"#), "{sql}");
    assert!(sql.contains(r#"'b' AS src"#), "{sql}");
}

#[test]
fn union_parenthesized_pipeline_operand() {
    let s = schemas(&[("a", &["ts", "msg"]), ("b", &["ts", "msg"])]);
    let sql = must_with(r#"union a, (b | where msg contains "x") | take 10"#, &s);
    assert!(sql.contains("LIKE"), "{sql}");
    assert!(sql.to_uppercase().contains("LIMIT 10"), "{sql}");
}

#[test]
fn union_trailing_ops_apply_to_union() {
    let s = schemas(&[("a", &["ts"]), ("b", &["ts"])]);
    let sql = must_with(r#"union a, b | where ts > datetime("2026-01-01T00:00:00Z") | take 5"#, &s);
    // WHERE must scope the union result, not a single branch.
    let upper = sql.to_uppercase();
    let union_pos = upper.find("UNION ALL").unwrap();
    let where_pos = upper.rfind("WHERE").unwrap();
    assert!(where_pos > union_pos, "trailing where must be outside the union: {sql}");
}

#[test]
fn union_unknown_table_errors() {
    let s = schemas(&[("a", &["x"])]);
    assert!(kql_to_sql_with_schemas("union a, nope", &s).is_err());
}

#[test]
fn union_without_schemas_errors_clearly() {
    let e = kql_to_sql("union a, b").unwrap_err();
    assert!(e.to_string().contains("schema"), "{e}");
}

#[test]
fn non_union_queries_unaffected_by_schema_api() {
    let s = schemas(&[("t", &["x"])]);
    assert_eq!(must_with("t | take 5", &s), kql_to_sql("t | take 5").unwrap());
}
```
