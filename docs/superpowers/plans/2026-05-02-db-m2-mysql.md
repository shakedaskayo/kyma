# DB Integration M2 — MySQL Slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **Prerequisite:** [DB M1 Postgres](2026-05-02-db-m1-postgres.md) is complete and committed.

**Goal:** Land `MySqlSource` against the M0 `ExternalSource` trait, with both federation and sync modes shipping end-to-end against MySQL 8.0. The federation pushdown reuses the engine-agnostic planner from M1; the MySQL-specific pieces are (a) the SQL renderer (slightly different identifier quoting and parameter style), (b) collation-safe column detection populated into `Capabilities::string_collation_safe_columns`, and (c) the binlog-based CDC. Sync uses `START TRANSACTION WITH CONSISTENT SNAPSHOT` + `SHOW MASTER STATUS` for the initial-snapshot LSN-equivalent (GTID + binlog file/position), then `mysql-binlog-connector-rust` (or equivalent) for the streaming events. Property tests gate every pushdown rule, with **MySQL collation tests** as the new bet-the-product layer.

**Architecture:** `MySqlSource` lives at `crates/kyma-connectors/src/external/mysql/`. The internal layout mirrors the Postgres slice (handle / introspect / scan / sql_render / snapshot / replication / types). Federation uses a `sqlx::MySqlPool`; CDC uses a separate dedicated `mysql_async` connection that issues `COM_REGISTER_SLAVE` + `COM_BINLOG_DUMP_GTID`. The collation-safety mechanism is the new architectural deliverable: at introspection time, every `string` column's collation is recorded; the `PushdownPlanner` consults `Capabilities::string_collation_safe_columns` per filter; case-insensitive collations force the filter into the residual.

**Tech Stack:** Rust 1.95, Tokio, `sqlx 0.8` with the `mysql` feature, `mysql_async 0.34` (or current) for binlog protocol, `mysql_common` for binlog event parsing, `arrow-array 53`, `datafusion 44`, `proptest`, `testcontainers_modules::mysql`. Spec: [`docs/superpowers/specs/2026-05-02-multi-source-database-integration-design.md`](../specs/2026-05-02-multi-source-database-integration-design.md). Builds on M0 + M1.

- [ ] **Step 1: Capabilities preset**

Write `crates/kyma-federation/src/mysql_dialect.rs`:

```rust
#![forbid(unsafe_code)]
//! MySQL capabilities profile. Mirrors the Postgres preset structurally;
//! `string_collation_safe_columns` is filled in dynamically at introspection
//! time per spec §6.3 — the planner consults it per filter.

use std::collections::BTreeSet;
use kyma_connectors::external::{AggFunc, Capabilities, FilterOp, TableQualifiedName};

pub fn mysql_capabilities() -> Capabilities {
    let mut filter_ops = BTreeSet::new();
    for op in [FilterOp::Eq, FilterOp::NotEq, FilterOp::Lt, FilterOp::LtEq,
               FilterOp::Gt, FilterOp::GtEq, FilterOp::In, FilterOp::IsNull,
               FilterOp::Like, FilterOp::And, FilterOp::Or, FilterOp::Not] {
        filter_ops.insert(op);
    }
    let mut function_allowlist = BTreeSet::new();
    for f in ["lower", "upper", "coalesce", "date_format"] {
        function_allowlist.insert(f);
    }
    let mut agg_funcs = BTreeSet::new();
    for f in [AggFunc::Count, AggFunc::CountDistinct, AggFunc::Sum,
              AggFunc::Avg, AggFunc::Min, AggFunc::Max] {
        agg_funcs.insert(f);
    }
    Capabilities {
        filter_ops, function_allowlist, agg_funcs,
        group_by: true, order_by: true, limit: true, same_source_join: true,
        string_collation_safe_columns: BTreeSet::new(),
    }
}

/// MySQL collations that are case-sensitive and binary-comparable.
/// Filters on string columns whose collation is NOT in this set are kept
/// above the scan in DataFusion. See spec §6.3.
pub fn collation_is_safe(collation_name: &str) -> bool {
    matches!(collation_name,
        "utf8mb4_bin" | "utf8mb4_0900_as_cs" | "utf8_bin" | "binary"
        | "utf8mb4_0900_bin" | "ascii_bin" | "latin1_bin")
}
```

- [ ] **Step 2: Wire and unit-test**

Inline tests for `collation_is_safe`:

## Task 5: SQL renderer (MySQL dialect)

**Files:**
- Modify: `crates/kyma-connectors/src/external/mysql/sql_render.rs`

- [ ] **Step 1: Render filters → MySQL SQL** with **backtick-quoted identifiers** and `?` placeholders. Otherwise structurally identical to the Postgres renderer.

- [ ] **Step 2: Crucial new rule** — when rendering `Eq`/`NotEq`/`Like` on a string column, consult the renderer's `Capabilities` snapshot: if the column is NOT in `string_collation_safe_columns`, return `None` so the planner keeps the filter as residual.

The renderer therefore needs the column-name → table mapping from the planner's perspective. Pass `&Capabilities` and `&InferredSchema` (the table currently being scanned) into `render_filter`. The Postgres renderer doesn't need this; we extend the shared signature in M2.

- [ ] **Step 3: Inline tests**

```rust
#[test] fn case_insensitive_string_filter_is_residual() {
    let caps = Capabilities { /* ... no string_collation_safe_columns */ ..mysql_capabilities() };
    let r = render_filter(&[col("name").eq(lit("alice"))], &caps, &name_schema_with_ci_collation());
    assert!(r.is_none(), "case-insensitive filter must be residual");
}

#[test] fn case_sensitive_string_filter_pushes() {
    let caps = mysql_capabilities_with_safe(&[("public","u","name")]);
    let r = render_filter(&[col("name").eq(lit("alice"))], &caps, &name_schema_with_safe_collation());
    assert!(r.is_some());
}

#[test] fn integer_filter_always_pushes() {
    // Numeric/timestamp filters never trigger the collation check.
}
```

## M2 Open Decisions Verified at Day-1

- The exact MySQL binlog Rust crate (`mysql_async` vs. an alternative) — verify it actually supports GTID-based `BinlogStreamRequest`. If not, fall back to `mysql-binlog-connector-rust` or comparable.
- The renderer signature change in Task 5 is breaking for the Postgres slice. Keep the shared signature symmetric; M1 Postgres renderer just ignores the new params.
- `bigint unsigned` overflow handling: M2 lands the warning-only path; user-facing flag for "fail loud" is a v1.5 follow-up.
