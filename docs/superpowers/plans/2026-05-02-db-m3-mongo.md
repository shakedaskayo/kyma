# DB Integration M3 — MongoDB Slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **Prerequisite:** [DB M2 MySQL](2026-05-02-db-m2-mysql.md) is complete and committed.

**Goal:** Land `MongoSource` against the M0 `ExternalSource` trait. MongoDB is the genuinely-new shape: federation pushes filter/projection/limit/sort/aggregation as a `$match`/`$project`/`$limit`/`$sort`/`$group` aggregation pipeline (different from SQL); sync uses `$changeStream` with `startAtOperationTime` for snapshot-consistent CDC; schema mapping flattens nested objects to dotted columns up to `scope.flatten_depth` (default 2) per spec §6.4. The `SchemaEvolver` is exercised hardest here — Mongo collections are schemaless, so the inference + dynamic-overflow + promote-from-dynamic state machine carries the integration. Property tests gate every pushdown rule for the aggregation pipeline. Mongo-specific tests cover polymorphic fields, nested flattening, and BSON type coercion.

**Architecture:** `MongoSource` lives at `crates/kyma-connectors/src/external/mongo/`. Federation wraps the `mongodb 3.x` Rust driver; `PushedPlan::MongoPipeline(Vec<Document>)` is consumed by `MongoSource::scan` which executes `db.coll.aggregate(pipeline)` and maps each BSON document into Arrow batches via the schema-evolver-driven shape. Sync uses the official driver's change-stream API with a `ChangeStreamOptions::start_at_operation_time` set to the cluster time at snapshot start. Type coercion lives in `mongo/types.rs` (the kyma docs site renders the table directly).

**Tech Stack:** Rust 1.95, Tokio, `mongodb 3` (or current; verify against the `agent-stack` constraint that pulls in `chrono >= 0.4.44`), `bson 2`, `arrow-array 53`, `datafusion 44`, `proptest`, `testcontainers_modules::mongo`. Spec: [`docs/superpowers/specs/2026-05-02-multi-source-database-integration-design.md`](../specs/2026-05-02-multi-source-database-integration-design.md). Builds on M0 + M1 + M2.

## Task 2: BSON → kyma TYPE_MAP

**Files:**
- Create: `crates/kyma-connectors/src/external/mongo/{mod.rs,types.rs}`
- Modify: `crates/kyma-connectors/Cargo.toml`

- [ ] **Step 1:** Cargo manifest gains `mongodb = { version = "3", optional = true }`, `bson = { version = "2", optional = true }`, and a `mongo` feature.

- [ ] **Step 2:** Type table per spec §6.4: `Int32 → int`, `Int64 → long`, `Double → real`, `Decimal128` per `scope.decimal128_mode`, `Boolean → bool`, `String → string`, `ObjectId → string` (24-char hex), `UUID (subtype 4) → string`, `Date → timestamp`, `BSON Timestamp → timestamp`, `Binary (other subtypes) → string` (base64), `Null` → NULL, `Array (any) → dynamic` for v1, `Object` (≤ flatten_depth) flattened, `Object` (> flatten_depth) → `dynamic`, `RegExp/JS/MinKey/MaxKey/DBPointer/Symbol → dynamic` with warn.

```rust
pub fn map_bson(t: &bson::Bson, depth: u32, max_depth: u32) -> KymaType {
    use bson::Bson::*;
    match t {
        Int32(_) => KymaType::Int,
        Int64(_) => KymaType::Long,
        Double(_) => KymaType::Real,
        Decimal128(_) => KymaType::Real, // mode-dependent: caller may force String
        Boolean(_) => KymaType::Bool,
        String(_) => KymaType::String,
        ObjectId(_) => KymaType::String,
        Binary(_) => KymaType::String,
        DateTime(_) => KymaType::Timestamp,
        Timestamp(_) => KymaType::Timestamp,
        Null => KymaType::String, // null doesn't determine type alone; caller usually skips
        Array(_) => KymaType::Dynamic,
        Document(_) if depth >= max_depth => KymaType::Dynamic,
        Document(_) => KymaType::Dynamic, // sub-fields are recorded separately by flattener
        _ => KymaType::Dynamic,
    }
}
```

## Task 4: Schema introspection by sampling

**Files:**
- Modify: `crates/kyma-connectors/src/external/mongo/introspect.rs`
- Modify: `crates/kyma-connectors/src/external/mongo/flatten.rs`

- [ ] **Step 1: Implement collection sampling**. For each collection in scope:
  1. `coll.aggregate([{$sample: {size: N}}])` for `N = min(1000, count)`.
  2. For each sampled doc: walk all top-level fields and (recursively to `scope.flatten_depth`) nested objects.
  3. Feed observations into a `SchemaEvolver::FieldObservation` per dotted path.
  4. After sampling, run `decide()` per field; the result is the initial `InferredSchema`.

- [ ] **Step 2: Implement flatten + path encoding** in `flatten.rs`:
  - `flatten(doc, depth, max_depth) -> HashMap<String, bson::Bson>` where keys are dotted paths.
  - Sub-objects beyond `max_depth` get encoded as `Bson::Document(...)` and left in the parent path (caller routes to `dynamic`).

## Task 5: Aggregation pipeline renderer

**Files:**
- Modify: `crates/kyma-connectors/src/external/mongo/pipeline.rs`

- [ ] **Step 1: Render filter `Expr` → `$match` document.** Cover the operators in the Mongo `Capabilities` set. Examples:

| DataFusion expr | BSON pipeline stage |
|---|---|
| `region = 'eu'` | `{$match: {"region": {"$eq": "eu"}}}` |
| `score > 0.5 AND region IN ('eu','us')` | `{$match: {"$and": [{"score": {"$gt": 0.5}}, {"region": {"$in": ["eu","us"]}}]}}` |
| `name LIKE 'A%'` | `{$match: {"name": {"$regex": "^A"}}}` (escape special chars) |
| `email IS NULL` | `{$match: {"email": null}}` (Mongo treats `null` as match `null` and missing) |

- [ ] **Step 2: Render projection** → `$project` stage. Field paths use dotted notation matching the flattener.

- [ ] **Step 3: Render limit/sort** → `$limit` / `$sort` stages.

- [ ] **Step 4: Render aggregation** (`COUNT`, `SUM`, `AVG`, `MIN`, `MAX` + `GROUP BY`) → `$group` stage.

- [ ] **Step 5: Reject unsupported expressions** by returning `None` (residual).

- [ ] **Step 6: Strict-bind discipline** — string literals are escaped via the BSON serialization path; never string-formatted into the pipeline document.

- [ ] **Step 7: Inline tests** for each shape.

- [ ] **Step 8: Commit**
