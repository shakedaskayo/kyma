# F2.1 — Gauntlet Orchestrator + CI Tiers + Perf Baseline — Design

**Status:** approved 2026-05-19. Ready for implementation plan.

**Parent:** F2 master spec at `docs/superpowers/specs/2026-05-19-f2-test-gauntlet-master-design.md`. F2.1 is the first of F2's five sub-specs; it defines the contract the other four (F2.2–F2.5) plug into.

**Estimate:** ~1 week.

---

## 1. Goal & non-goals

### Goal

Ship the connective tissue for the gauntlet: an orchestrator script, three CI tier workflows, and a perf-regression baseline. After F2.1 lands, F2.2–F2.5 each implement their respective family by dropping a single script under `scripts/gauntlet/` that the orchestrator already knows how to invoke.

F2.1 itself fully implements one family — `perf-regression` — and leaves placeholders for the other four. Placeholder scripts return `pass: false, reason: "not yet implemented"`. This means F2.1's PR-tier gauntlet workflow is expected to *fail* until F2.2 (property + fuzz) lands and the placeholder is replaced. That's intentional: F2.1 ships the contract, not the contents.

### Non-goals

- Implementing property+fuzz, sim, chaos, or soak scripts. Those are F2.2–F2.5's job.
- Modifying or replacing the F1-shipped `.github/workflows/backcompat.yml`. The gauntlet references back-compat as an "external" family and prints a pointer.
- Provisioning self-hosted runners. F2.1 targets GHA hosted runners only.
- Capturing the initial baseline numbers via local laptop runs. Baseline capture must happen on `ubuntu-22.04` GHA runner via a manually-triggered workflow.

## 2. Components

| Artifact | Owner phase | Responsibility |
|---|---|---|
| `scripts/gauntlet.sh` | F2.1 | Top-level orchestrator. Required arg `--tier=pr\|nightly\|weekly`. Dispatches to per-family scripts, collects JSON results, prints summary, exits 0 if all non-SKIP families passed, 1 otherwise. |
| `scripts/gauntlet/property-fuzz.sh` | F2.1 placeholder → F2.2 | Returns `{ pass: false, reason: "not yet implemented in F2.1 placeholder" }`. |
| `scripts/gauntlet/sim.sh` | F2.1 placeholder → F2.3 | Same placeholder shape. |
| `scripts/gauntlet/chaos.sh` | F2.1 placeholder → F2.4 | Same placeholder shape. |
| `scripts/gauntlet/soak.sh` | F2.1 placeholder → F2.5 | Same placeholder shape. |
| `scripts/gauntlet/perf-regression.sh` | F2.1 (fully implemented) | Invokes `perf-baseline.sh` then `perf-check.sh`; emits JSON. |
| `scripts/perf-baseline.sh` | F2.1 | Brings up (or assumes) a live engine, ingests reference dataset (with warm-up phase), runs reference query set K times, emits metrics JSON. |
| `scripts/perf-check.sh` | F2.1 | Reads current metrics + checked-in baseline; fails if tolerance breached (gated by `GAUNTLET_PERF_ENFORCE=1`; default `0` for warn-only). |
| `scripts/perf-capture-baseline.sh` | F2.1 | One-command baseline capture script. Designed to be invoked from a `workflow_dispatch` workflow on `ubuntu-22.04`. Outputs a new `perf-baseline.json`. |
| `scripts/fixtures/perf-baseline.json` | F2.1 | Checked-in baseline. Schema: `{ ingest_rps, query_p50_ms, query_p99_ms, ingest_total_rows, captured_at, hardware_label, pensieve_git_sha }`. |
| `scripts/fixtures/perf-baseline/seed.ndjson` | F2.1 | Pinned ~10 MB deterministic reference dataset. Hand-crafted to exercise the 3-level pruning cascade. |
| `scripts/fixtures/perf-baseline/queries.txt` | F2.1 | Reference query set (5–10 queries) covering: wide-time-range scan, narrow-time-range catalog pruning, equality-index pruning, token-contains block pruning. |
| `.github/workflows/gauntlet-pr.yml` | F2.1 | On PR to main. Runs `gauntlet.sh --tier=pr`. |
| `.github/workflows/gauntlet-nightly.yml` | F2.1 | `cron: "0 3 * * *"` + `workflow_dispatch`. Runs `--tier=nightly`. |
| `.github/workflows/gauntlet-weekly.yml` | F2.1 | `cron: "0 4 * * 0"` + `workflow_dispatch`. Runs `--tier=weekly`. |
| `.github/workflows/perf-baseline-capture.yml` | F2.1 | `workflow_dispatch` only. Runs `perf-capture-baseline.sh`, opens a PR with the updated baseline JSON. |

### Per-family output contract

Every family script must emit a single JSON object on stdout:

```json
{
  "family": "property-fuzz | sim | chaos | soak | perf-regression",
  "tier": "pr | nightly | weekly",
  "started_at": "2026-05-19T22:30:00Z",
  "finished_at": "2026-05-19T22:32:14Z",
  "pass": true,
  "observations": ["..."]
}
```

The orchestrator parses this JSON. Anything else printed (engine logs, intermediate output) goes to stderr or to a per-family log file.

### Top-level summary

`gauntlet.sh` prints a human-readable summary at the end:

```
=== gauntlet --tier=pr summary ===
property-fuzz:  FAIL (placeholder)        — 0.2s
sim:            FAIL (placeholder)        — 0.2s
chaos:          SKIP (not in pr tier)
soak:           SKIP (not in pr tier)
perf:           SKIP (not in pr tier)
backcompat:     external (see .github/workflows/backcompat.yml)
=== overall: FAIL ===
```

And a structured `gauntlet-results.json` artifact in `$GITHUB_WORKSPACE` (or current dir locally) with the full results array.

## 3. Tier scope

| Family | PR (~5–10 min) | Nightly (~1–2 h) | Weekly (~6 h cap) |
|---|---|---|---|
| `property-fuzz` | Smoke: proptest + 60s / fuzz target | Full: proptest + 10 min / fuzz target | Same as nightly |
| `sim` | Subset (1–2 fastest scenarios) | Full (all invariant + Axis-1 scenarios) | Same as nightly |
| `chaos` | SKIP | Full (all 4 scenarios) | Same as nightly |
| `soak` | SKIP | 1 h | 6 h |
| `perf-regression` | SKIP | Full (reference dataset + tolerance check) | Same as nightly |
| `backcompat` | External (separate workflow) | External | External |

Time budgets are guidance, not contracts. F2.2–F2.5 measure actual runtime during their implementations and may need to renegotiate.

**Tier dispatch in `gauntlet.sh`:**

```bash
case "$TIER" in
  pr)
    run_family property-fuzz pr
    run_family sim pr
    ;;
  nightly)
    run_family property-fuzz nightly
    run_family sim nightly
    run_family chaos nightly
    run_family soak nightly
    run_family perf-regression nightly
    ;;
  weekly)
    run_family property-fuzz nightly  # nightly == weekly for fuzz/sim/chaos/perf
    run_family sim nightly
    run_family chaos nightly
    run_family soak weekly
    run_family perf-regression nightly
    ;;
esac
```

`run_family` is a bash function that invokes `scripts/gauntlet/<family>.sh --tier=<tier>`, captures its stdout JSON, appends to a results array, tracks the worst-case exit (pass = all-pass).

**Workflow schedules:**

- `gauntlet-nightly.yml`: `cron: "0 3 * * *"` (3 AM UTC daily; off-peak for hosted runners).
- `gauntlet-weekly.yml`: `cron: "0 4 * * 0"` (4 AM UTC Sunday).
- Both also support `workflow_dispatch` for manual runs.

## 4. Per-script interfaces

### `gauntlet.sh`

```
Usage: gauntlet.sh --tier=pr|nightly|weekly [--engine-url=URL] [--results=PATH]

Required:
  --tier=<pr|nightly|weekly>

Optional:
  --engine-url=URL         Override engine endpoint (default: http://localhost:8080).
  --results=PATH           Where to write gauntlet-results.json (default: ./gauntlet-results.json).

Exits 0 if all non-SKIP families pass, 1 otherwise.
Engine startup/teardown is the workflow's responsibility, not the orchestrator's.
```

### `scripts/gauntlet/perf-regression.sh`

```
Usage: perf-regression.sh --tier=<tier>

Reads:
  $PENSIEVE_HTTP_ADDR or http://localhost:8080
  scripts/fixtures/perf-baseline.json
  scripts/fixtures/perf-baseline/seed.ndjson
  scripts/fixtures/perf-baseline/queries.txt

Emits to stdout:
  Per-family JSON object (see contract above).

Exits 0 always (warn-only by default).
Exit 1 only if GAUNTLET_PERF_ENFORCE=1 and tolerance breached.
```

### `scripts/perf-baseline.sh`

```
Usage: perf-baseline.sh [--engine-url=URL] [--target-rows=N]

Default target: 100,000 rows (ingests seed.ndjson 1000 times, each copy = ~100 rows).

Phases:
  1. Ingest reference dataset to target row count. Measures wall-clock seconds.
  2. Warm-up: runs reference query set once, discards timings.
  3. Measure: runs reference query set K=10 times, records per-call latency.
  4. Emit metrics JSON to stdout:
     {
       "ingest_rps": <float>,
       "query_p50_ms": <float>,
       "query_p99_ms": <float>,
       "ingest_total_rows": <int>,
       "ingest_total_seconds": <float>,
       "captured_at": "<RFC3339>",
       "hardware_label": "<env var GAUNTLET_HARDWARE_LABEL or 'unknown'>",
       "pensieve_git_sha": "<git rev-parse HEAD>"
     }
```

### `scripts/perf-check.sh`

```
Usage: perf-check.sh <current.json> <baseline.json>

Reads current run metrics and checked-in baseline.
Computes per-metric ratio. Fails if:
  ingest_rps < 0.9 * baseline.ingest_rps
  query_p50_ms > 1.1 * baseline.query_p50_ms
  query_p99_ms > 1.1 * baseline.query_p99_ms

Behavior:
  Default (warn-only): always exits 0; emits per-metric pass/fail in JSON.
  GAUNTLET_PERF_ENFORCE=1: exits 1 if any metric out of tolerance.

Emits to stdout:
  {
    "current": { ...metrics... },
    "baseline": { ...metrics... },
    "comparisons": [
      { "metric": "ingest_rps", "current": X, "baseline": Y, "ratio": Z, "pass": bool }
    ],
    "enforce_mode": bool,
    "overall_pass": bool
  }
```

### `scripts/perf-capture-baseline.sh`

```
Usage: perf-capture-baseline.sh [--engine-url=URL]

Wrapper that:
  1. Starts a fresh engine + docker-compose stack (or assumes pre-running).
  2. Runs perf-baseline.sh.
  3. Saves output as scripts/fixtures/perf-baseline.json.
  4. Prints next-steps: "Commit this file and open a PR against main with title 'perf: re-baseline against ...'."

Intended invocation: from `.github/workflows/perf-baseline-capture.yml` via workflow_dispatch.
Sets GAUNTLET_HARDWARE_LABEL=ubuntu-22.04-gha (or whatever the runner type is).
```

### Reference dataset (`scripts/fixtures/perf-baseline/seed.ndjson`)

~10 MB of pinned NDJSON rows. Schema matches `obs.otel_logs` so the existing query infrastructure works. Hand-crafted to:

- Span ~24 hours of synthetic timestamps (exercises time-range pruning at multiple granularities).
- Contain ~5 distinct `service.name` values (exercises equality-index pruning).
- Contain ~3 distinct `severity_text` values (exercises low-cardinality pruning).
- Embed a small `attributes` dynamic object with searchable token values (exercises token-index pruning).

`perf-baseline.sh` ingests this NDJSON N times to reach the target row count (default 100k).

### Reference query set (`scripts/fixtures/perf-baseline/queries.txt`)

Tab-separated, same format as `scripts/backcompat-queries.txt`. 5–8 queries exercising the pruning cascade:

```
q-scan-broad      POST /v1/query  application/sql  obs  SELECT COUNT(*) FROM otel_logs
q-prune-time      POST /v1/query  application/sql  obs  SELECT COUNT(*) FROM otel_logs WHERE timestamp >= '<narrow window>'
q-prune-equality  POST /v1/query  application/x-kql  obs  otel_logs | where service.name == "svc-a" | summarize n = count()
q-prune-token     POST /v1/query  application/x-kql  obs  otel_logs | where attributes contains "specific_value" | summarize n = count()
q-multi-pruning   POST /v1/query  application/sql  obs  SELECT severity_text, COUNT(*) FROM otel_logs WHERE timestamp >= '<narrow>' AND "service.name" = 'svc-a' GROUP BY severity_text
```

Each query runs K=10 times during measurement; p50 and p99 computed across all queries × all runs.

## 5. Decisions taken + risks

### Decisions taken (locked at design time)

| Decision | Choice |
|---|---|
| Perf in PR tier? | **Nightly only.** PR stays fast. |
| Backcompat relationship | **Keep as separate workflow.** Gauntlet references it. |
| Failure handling | **Run all families, exit non-zero if any failed.** No fail-fast. |
| Perf enforce-vs-warn at v1.0 | **Warn-only by default** (`GAUNTLET_PERF_ENFORCE=0`); flip to enforce after baseline numbers have stabilized across a few weeks of nightly runs. |
| Reference dataset | **New pinned `seed.ndjson` ~10 MB** (NOT reusing `seed-demo-data.sh`'s random patterns; perf needs determinism). |
| Reference workload | **5–8 queries** covering broad scan + time prune + equality prune + token prune + multi-pruning. K=10 reps. |
| Baseline capture procedure | **Manual `workflow_dispatch` workflow** on ubuntu-22.04 GHA runner. PR opened automatically with new baseline. |
| Tier schedules | **Nightly: `0 3 * * *`. Weekly: `0 4 * * 0`.** Both UTC. Both support `workflow_dispatch`. |

### Risks to monitor during implementation

- **Tolerance bands might be too tight or too loose initially.** F2.1 ships with 10% bands; the first few weeks of nightly runs will tell us whether to widen or narrow. The `GAUNTLET_PERF_ENFORCE=0` default ensures we don't false-positive merge blocks during this period.
- **Warm-up phase may be insufficient.** First measurement after engine cold-start can still be jittery. F2.1 implementation should run a brief sanity check (e.g. capture baseline twice in a row, see if numbers are within 5%) before declaring the baseline canonical.
- **Reference dataset shape decisions.** What exact attribute values, what time distribution, what cardinality? F2.1 implementation will make these calls; design only locks the structure. If pruning numbers turn out trivial (everything pruned to ~0 rows) the dataset needs more density; if pruning rarely fires (every query scans everything) the dataset needs more shape.
- **GHA Actions billing dependency** (unchanged from F1/F2 master). All four new workflow files run only when billing is unblocked. F2.1 local validation (`gauntlet.sh --tier=pr` against a local engine) is the bridge.
- **`gauntlet.sh` orchestrator complexity creep.** Resist adding features beyond "dispatch, collect, summarize, exit." If we need fancier orchestration (parallelism, dependencies between families, retries), revisit in a follow-up after F2.2–F2.5 ship.

## Appendix — Implementation outline

(Not the full implementation plan — the F2.1 brainstorm transitions to `writing-plans` next. This is the rough shape that plan will detail.)

Phases the plan will likely follow:

1. **Skeleton scripts** — `gauntlet.sh` + 5 placeholder family scripts + perf-regression.sh stub that just emits placeholder JSON.
2. **gauntlet.sh dispatch + results collection** — TDD: test that it correctly routes per tier, collects JSON, returns the right exit code.
3. **perf-baseline.sh** — TDD'd against a running engine; emits valid JSON.
4. **perf-check.sh** — TDD'd against two JSON inputs; tolerance logic; enforce-vs-warn mode.
5. **Reference dataset + queries** — hand-craft `seed.ndjson` + `queries.txt`; smoke against a local engine.
6. **perf-capture-baseline.sh + workflow** — wires the manual-capture pipeline.
7. **CI workflows** — three tier workflows plus the perf-baseline-capture workflow.
8. **Initial baseline capture** — manually trigger the baseline workflow once; merge the resulting `perf-baseline.json`.
9. **Self-review + PR** — verify all outputs exist, all workflows parse, open PR.
